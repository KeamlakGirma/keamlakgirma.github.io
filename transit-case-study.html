Why this exists

Getting around Addis Ababa means switching apps and mental models.

Ride‑hailing apps cover taxis. Paper tickets still cover most buses. The light‑rail line runs on its own schedule with its own queue at the counter. Riders mix all three in a single trip, but nothing ties the trip together — the booking, the map, and the ticket live in three different places.

This project explores what it looks like to collapse that into one app: pick a mode, pick real stations (Megenagna, Mexico Square, Summit), see the route drawn on a map, pay through a provider people already use — TeleBirr, CBE Birr, or YenePay — and receive a scannable QR ticket instead of a paper stub.

Under the hood

A thin client, a small API, one database

The app leans on Redux Toolkit for local trip state and a small Express API for the one thing that has to be server‑side: accounts.

Mobile client

  • React Native + Expo
  • Redux Toolkit (origin, destination, ETA, ticket)
  • React Navigation — stack + drawer
→

API server

  • Node.js + Express
  • Joi request validation
  • bcrypt password hashing · JWT sessions
→

Data

  • MongoDB (Atlas)
  • Mongoose User schema
  • Ticket + QR reference per user

Google Maps Platform

  • Places Autocomplete — origin search
  • Directions — route polyline
  • Distance Matrix — ETA

The mobile client talks to Maps directly for anything map‑related; it only calls the Express API for sign‑up, login, and reading back a ticket.

Engineering notes

What's solid, and what's next

Written the way I'd walk a reviewer through the repo — including the parts that are still rough.

01

Sign‑up is wired end to end

The registration flow validates input with Joi, checks for duplicate emails and usernames, salts and hashes the password with bcrypt, and persists the user via Mongoose — a complete, working path from form to database.

02

Login is the next thing to finish

The auth route is scaffolded (JWT issuance, password comparison) but not fully wired to the lookup it depends on yet — it's the clear next task before this could handle real sessions.

03

Secrets need to move to .env

Map and database keys are currently inline in a few files for speed while prototyping. Rotating them and reading from environment variables is the first hardening step before any public deploy.
